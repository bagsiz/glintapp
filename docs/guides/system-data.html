What is “System Data” on a Mac, and how do you shrink it?

Last updated 13 November 2026

Open System Settings › General › Storage and there is often a large grey bar called “System Data”. It's a catch‑all, not a single thing, which is why it's hard to clean by hand.

What ends up in System Data

macOS puts files that don't fit its other categories (Applications, Documents, Photos, Mail and so on) under System Data. Depending on your Mac and macOS version it can include:

  • Caches and logs written by apps and by macOS itself.
  • Time Machine local snapshots, kept on the internal disk between backups.
  • Virtual memory: swap files and the sleep image.
  • App support data in ~/Library/Application Support and app containers.
  • Developer and virtual-machine data: Xcode build folders and simulators, Docker disk images, VM disks.

Because several of these grow and shrink on their own, the number can change between two looks at the Storage pane.

How to shrink it safely

1. Restart

Swap files are cleared at restart. If your Mac has been up for weeks, a restart alone can give back several gigabytes.

2. Check local snapshots

macOS removes Time Machine snapshots by itself when space runs low, but you can list them in Terminal:

tmutil listlocalsnapshots /

A specific snapshot can be removed with sudo tmutil deletelocalsnapshots <date>, using the date from the list.

3. Clear caches and logs

Caches are rebuilt by the apps that made them, so clearing them is usually safe (see Is it safe to delete ~/Library/Caches?). Quit the apps first.

4. Clean developer leftovers

Xcode's DerivedData, old simulators, and package-manager caches (npm, pnpm, Gradle, Cargo) can reach tens of gigabytes. Xcode can delete unavailable simulators with xcrun simctl delete unavailable. For Docker, docker system prune removes stopped containers and unused images, so read its prompt before you confirm.

5. Find the big folders

Look for large folders before deleting anything. Many folders that count toward System Data are hidden from apps that don't have Full Disk Access, so give your disk tool that permission before trusting its totals.

Don't delete things in /System, /private/var or /Library at random. Some of those files belong to macOS and other users, and removing the wrong one can stop your Mac from booting or apps from launching.
